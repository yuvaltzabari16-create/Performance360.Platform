# Known issues and accepted risks

| Item | Where | Why it is accepted | Revisit |
| --- | --- | --- | --- |
| `npm audit` reports advisories for the PostCSS copy bundled inside Next 15 (GHSA-qx2v-qp2m-jg93 and related) | production dependency tree | The advisories need attacker-controlled CSS to be processed. The app only builds its own stylesheet. The fix ships only with Next 16 (a breaking upgrade). | When upgrading to Next 16 |
| `npm audit` reports advisories in the test runner (`vitest`, `tinypool`, `@vitest/mocker`) | dev dependencies only | Never shipped or run in production; runs only on developer machines and CI. | On the next Vitest major upgrade |
| Delete functions (account, GPS session, file) are not applied by the assistant's database connection | `supabase/manual/pending_delete_functions.sql` | The connection asks for a confirmation that cannot be answered there. Run the file once in the Supabase SQL editor. | After it has been run, delete this row |
| Attachments are stored in Postgres (5 MB limit) and only checked for plausible content, not scanned for viruses | `public.attachments`, `src/lib/files/rules.ts` | Keeps files under the same row-level security as their record and is testable without extra services. | Move to Supabase Storage with a virus scanner (for example ClamAV) before large-scale use (ADR 0004) |
| Rate limiter counters are in memory per server instance | `src/lib/security/rate-limit.ts` | Fine for one instance; several instances each count separately. | Shared store or platform firewall before scaling out |
| WHOOP integration is written from WHOOP's public documentation and tested against a built-in fake provider, not the live service | `src/lib/wearables/whoop.ts` | The developer docs could not be opened from the build environment. | First connection with real WHOOP credentials: check endpoint paths and field names |
| Scheduled WHOOP sync runs once a day and needs `CRON_SECRET` and the service-role key; no webhooks | wearables | Vercel's free plan allows one cron run a day. | Shorter interval on a paid plan, or WHOOP webhooks |
| Fitbit has no live connection | wearables | Fitbit Web API closes 30 Oct 2026; Google Health API needs Google approval. | When access is granted |
| Live GPS sync (StatSports, Catapult, Polar) is not built | GPS | Needs the club's vendor API credentials; file import works today. | When credentials exist |
| Legal texts are a working draft | `/privacy`, `/terms` | Shown with a draft notice until `LEGAL_REVIEWED=1`. | Before public launch |
| The interactive demo artifact runs on browser sample data and has no GPS, file or consent pages | claude.ai artifact | It is a showcase, not the product. | When the product is deployed |
| An athlete a coach created personally stays visible to that coach even when outside their squads | squads | The coach-athlete link is separate from team squads. | If clubs want squads to override it |
| End-to-end specs were written for Performance360 and have not been run against Performance360 Academy | `e2e/*.spec.ts` | They need a running app and a Supabase project; Performance360 Academy has none yet. Specs for the closed GPS, return-to-play and wearables modules were removed. Expect label and menu assertions (for example "My Team", "Training Planner", the personal-trainer account) to need updating. | First run against the academy's Supabase project |
| Closed modules still exist in code and in the database | `src/lib/permissions.ts` | Keeps the schema identical to Performance360 so fixes can be pulled across; the modules are unreachable from the menu and their pages redirect. | If the academy decides it never needs them |
